## Stage A — ecosystem and product understanding, days 1–2

Current pass: source discovery, three read-only specialist reviews, founder
interview, source visual inspection and Curious entry/chart observation.

Status: source discovery and bounded planning packet prepared. The founder
confirmed whole-system-first, founder/operator scope with tenant/role isolation,
and decisions plus launch of admitted work. A historical Fitcheck lineage is
selected and traced. Current authenticated eligibility, native platform probes
and founder perceptual review are implementation dependencies, not claimed
discovery results. No native implementation has run.

Discovery findings and next-stage dependencies:

- Preserve all three answered product decisions; record further choices as open.
- Reconcile every proposed visible connection to an owner, schema and evidence
  level. Distinguish source inventory from installed and live state.
- Use the traced dated Fitcheck lineage as a realistic reference, then select
  current authorized work for native live acceptance during implementation.
- Review Mission horizon renewal as its own doctrine question.
- Explore value and human context, not only constraints: what meaningful work
  is supported, what deserves attention and what can be learned?

Discovery exit: source-backed topology, named unknowns, independently reviewed
planning packet and explicit first daily job. Founder perceptual approval of
visual studies remains Stage B evidence. No native scaffold is required to close
the source-discovery objective.

## Stage B — interaction and visual contract, days 2–3

Create two comparable Canopy/dossier interaction studies using the actual art
lineage: one calm 2D overview and one optional spatial lens. Both must show the
same selected work, gap, evidence and next step. Use synthetic input visibly.

Prototype the whole-system → selected work → evidence → next step flow, source
versus runtime lens, search, inspector and return. Add denied/stale/missing data,
keyboard, readable text, reduced motion and empty states from the outset.
Both studies must also include the same visibly synthetic decision → admission →
launch → result/recovery scenario. Show changed admission, unsupported plant,
busy launch and outcome unknown, plus exact confirmation and original-request
recovery. A review of only the intermediate viewer cannot select the v1 visual
contract. Spatial navigation must not be required for a consequential action.

Exit: founder perceptual review of the core flow, design-kit direction, screen
map and proposed story acceptance. A beautiful terrain plate alone is not a UI.

## Stage C — native platform and identity spikes, days 3–4

Decide the supported OS/architecture and installation coexistence. Probe a
minimal native build, 2D/optional spatial tradeoff, local runtime access,
authentication/callback, denied/expired identity, offline cache and accessibility.
Use current Apple documentation; no reliance on partially fetched API pages.

Exit: measured foundation choice and precise native identity contract. The
new app contains no owner signing key, copied browser/native session store,
cross-tenant cache or direct operational database writer.

## Stage D — useful read-only native slice, days 4–6

Apply Bama scaffold conventions inside `apps/cambium-mac` without nested Git
initialization or overwriting the existing installation. Build immutable domain,
structurally separate read adapters, semantic design kit and local preferences.
Implement proposed stories S-003 through S-007 against labelled fixtures first,
then one reviewed authenticated owner read.

Exit: an app useful for one day: Canopy, dossier, evidence, understandable next
step, restart and offline behavior. Actual native snapshots and keyboard/VoiceOver
evidence are required. Local proof does not establish production acceptance.

## Stage E — bounded knowledge and runtime joins, days 6–8

Attach user-selected Field Theory sources/Possible nodes, scoped cited Cortex
references and redacted runtime observations. Reconcile exact repository identity
and reader scope before displaying operational context. Keep Field Report as its
own adapter; do not rename its schema into a Field Theory bridge.

Exit: explicit producer → envelope → consumer readback for each implemented
adapter; absent/unsupported dependencies stay usable and honest. No unselected
corpus ingestion, generation job, sync write or schedule activation.

## Stage F — decisions, admitted launch and result continuity, days 8–12+

Only after native identity and read paths are proven, implement complete proposal
review, exact confirmation, canonical status and original-tuple recovery. Build
the owner-reviewed native launch capability for supported Hands/Hermes work,
atomic admission revalidation, durable request identity, run readback and restart
reconciliation. Existing runner claim/outcome routes are not a native-founder
launch API. Keep decision, connection, execution and acceptance independent.
Do not use a live business approval merely to test UI behavior.

Exit: S-011–S-013 and S-017–S-020 pass their promoted ISA criteria, with meaningful
local negative tests and separately scoped real native decision/launch acceptance.
An approved graph change does not claim Hermes execution, useful artifact
acceptance or learned policy. This stage is required for the first usable release.

## Stage G — minimum founder release, days 12–14+

Complete S-014/S-016 across the full decision/launch/result/recovery journey.
Choose the founder distribution route and required signing/notarization policy,
build the exact artifact, verify install/coexistence with the existing Cambium,
and test native identity expiry, offline restart, update and recovery on the
intended Mac. Preserve an explicit rollback/recovery route.

Exit: identified source/artifact, actual native decision and admitted-launch
acceptance for the supported class, accessibility and install/recovery evidence.
This minimum artifact gate is required before claiming the first usable release;
a source-only build or local fixture cannot replace it.

## Stage H — broader distribution and optional expansion, later

Confirm or expand the initial distribution audience, signing/notarization/update policy,
retention and export, support, small entry points and optional notifications.
Verify the actual artifact on the intended Mac. Any Electron/Curious migration
or retirement requires reviewed parity and a recovery plan; the new source
directory does not retire a working product.

## Implementation packet ownership and critical path

| Packet | Proposed owning code/surface | Depends on | Required proof before downstream work |
| --- | --- | --- | --- |
| Native domain/read envelope | `apps/cambium-mac` domain/read modules | Architecture and current Worker envelope | Cross-language digest vectors, strict scope/time/join/cap decoding |
| Native design/interaction | `apps/cambium-mac` DesignKit/scenes | Source asset lineage and full action scenario | Founder task review, accessible linear equivalent, all interaction states |
| Native identity and action contracts | Cambium identity/action owners; Plexus/Access owner where required | Exact supported founder scope and server contract | Callback/exchange/role/tenant and current admission checks; no assumed login inheritance |
| Native decision client | `apps/cambium-mac` GateClient/coordinator | Identity + existing canonical Gate | Complete review/confirmation/CAS/expiry and original-tuple status tests |
| Native launch owner/client | Owning Cambium/Temperance/Hermes service plus `apps/cambium-mac` LaunchClient | Exact admitted work class/pin/plant; owner-reviewed new capability where needed | Atomic revalidation, durable request/status identity, busy/unknown/restart without duplicate dispatch |
| Knowledge/runtime adapters | Separate native Field Theory/Cortex/Field Report/runtime clients | Exact owner schema and selected sources | Scope, source provenance, absent/denied/stale behavior; no raw corpus or implicit writeback |
| Native run/evidence UI | Native RunClient/N11 and evidence inspector | Launch owner readback | Task/request/attempt/artifact binding and independent acceptance gap |
| Minimum native release | Native build/package/install surface | Full core and signed native proofs | Exact artifact, coexistence, permissions, accessibility and recovery on intended Mac |

The critical path is identity + exact launch-owner contract → decision/launch
coordination → real native action/result/recovery → founder artifact acceptance.
Resolve the action-owner interfaces during Stage C, before building a convincing
button against an unimplemented backend. Design and source-only read/knowledge
work may proceed in parallel. Cross-repository implementation is delivered in
its owning task; this plan grants no host/provider/cloud configuration change.
