<interfaces>
- Inventory generation accepts exactly `--source-revision REV --format json` or `--source-revision REV --format markdown`; optional `--root PATH` exists only for contained test repositories.
- There is no default revision and no `--write`, `--check`, `--output`, staged/index, publication, runtime/provider, or external destination option. `HEAD` is valid only when explicitly supplied and is immediately serialized as its resolved full SHA.
- Each invocation builds and validates one inventory object, then selects one pure renderer. JSON stdout is exactly one parseable object plus a final newline; Markdown stdout is exactly one complete document.
- Successful generation produces no stderr. Rejection is nonzero, produces no partial stdout document, and emits only bounded repository-relative diagnostics without checkout paths or source bodies.
- `scripts/check-documentation-inventory.mjs --source-revision REV` generates JSON twice and Markdown twice in memory, proves byte determinism, parses/validates JSON, and proves parity for full SHA, schema, inventory/source-set digests, entry count and paths, lifecycle values, canonical anchors, and exception facts. It performs no writes.
- Package scripts are exactly format/check dispatchers: `docs:inventory:json` fixes only `--format json`, `docs:inventory:markdown` fixes only `--format markdown`, and `docs:inventory:check` fixes no revision. Every public package invocation uses `npm run --silent docs:inventory:{json,markdown,check} -- --source-revision <REV>` so npm lifecycle banners cannot contaminate machine or human stdout.
- No `docs/documentation-inventory.v1.json` or `docs/documentation-inventory.md` file is created, referenced as a repository artifact, or added to Git.
</interfaces>
