# Plan 01-01: D1-Leased Service-Agreement Draft

## Objective

Ship one synthetic, internal-only service-agreement draft through Cambium D1 intake and leasing, Hermes execution, Temperance DOCX rendering, R2 persistence, terminal outcome, and authenticated readback.

## Deliverable Manifest

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| D1 | Cambium business-task contract and D1/R2 persistence | strict intake, fencing, task/artifact readback, replay tests |
| D2 | Hermes typed business executor | leased dispatch, shell-free Temperance invocation, upload/outcome receipt |
| D3 | Temperance service-agreement renderer | pinned policies, valid DOCX, watermark, no-signature warning |
| D4 | Versioned releases and rollback evidence | clean commits, checksums, previous live versions retained |
| D5 | Live synthetic proof | one task, one artifact, terminal receipt, digest parity, healthy services, revoked SSH |

## Tasks

1. Add the strict business intake, business-task table, artifact metadata, active-fence validation, R2 storage, and authenticated readback to Cambium.
2. Extend Hermes with the typed service-agreement command, safe subprocess adapter, exact-byte SHA-256 verification, artifact upload, business attestation, and runner configuration.
3. Extend the headless Temperance release with the pinned Thoughtseed contract/DOCX renderer and standalone validation gates.
4. Run all three local test suites from clean worktrees and commit immutable release candidates.
5. Export D1, apply the additive migration, deploy the backward-compatible Worker, install Temperance, and deploy Hermes with execution still disabled.
6. Roll Hermes back one version with the new Worker/migration in place, verify zero orphaned business tasks, and restore the new release.
7. Enable only native execution, submit the synthetic intake, verify lease/artifact/outcome/readback parity and task-scoped authorization, then replay the intake and a re-lease path.
8. Restore the safe runtime boundary, record GSD/ISA evidence, verify health, and revoke temporary SSH ingress.

## Checkpoints

- CP1: No production mutation before pre-build Advisor accepts the contracts and rollback order.
- CP2: D1 export is private and non-empty before migration.
- CP3: Worker health and previous version are retained before Hermes deployment.
- CP4: Hermes deployment keeps both execution flags false until all local and live preconditions pass.
- CP5: The only enabled business command is `service_agreement.draft.render`.
- CP6: Live task state must be `awaiting_human_approval`; any delivery or signature signal aborts the slice.
- CP7: Temporary SSH ingress is revoked even on failure.
- CP8: R2/D1 artifact creation is conditional on the stable task+directive-version identity and an exact SHA-256 match.
- CP9: Worker readback authorizes the caller against the requested task, not merely the bearer-token validity.
