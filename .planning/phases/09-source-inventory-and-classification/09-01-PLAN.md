## Objective

Create a provenance-bound, authenticated read-only inventory and
classification packet for the `9d9d` source against the `thoughtseed-labs`
target. Stop before every mutation and preserve exact conflicts for review.

## Tasks

### 1. Confirm read-only authority and access path

- Read the checked-in Wrangler profiles and Phase 8 resource map.
- Confirm the approved authenticated read path and secret names without
  printing values, tokens, cookies, headers, or session identifiers.
- Record the source and target account/profile identity required for the
  inventory; do not infer authority from a health endpoint or bucket total.
- If authenticated source-only access is unavailable, stop with a blocked
  receipt and do not substitute aggregate observations.

### 2. Capture deterministic source and target manifests

- Enumerate only the approved source and target namespaces.
- Capture exact object keys, bounded metadata, sizes, timestamps when supplied
  by the provider, and SHA-256 content digests.
- Normalize ordering and redact secret-shaped or machine-local values.
- Preserve the command, profile, source revision, and generated-at evidence in
  the review packet without storing credentials or mutable session material.

### 3. Classify every observed delta

- Classify records as `matching`, `source-only`, `target-only`,
  `target-newer`, or `digest-conflict`.
- Treat missing metadata, ambiguous identity, inaccessible objects, and digest
  disagreement as explicit blockers.
- Do not create an allowlist, copy plan, deletion plan, retirement claim, or
  parity claim from incomplete evidence.

### 4. Package verification and handoff

- Verify repeated generation is byte-identical for the same pinned inputs.
- Verify the JSON parses and the Markdown readback names the same counts,
  keys, classifications, blockers, source revision, and target profile.
- Append a bounded handoff entry with the exact next planning or approval step.
- Stop at the Phase 9 verification boundary; Phase 10 and the D1/Hermes v0.6
  horizon remain unexecuted.

## Verification contract

| Criterion | Probe |
|---|---|
| Authenticated read path is bounded | Redacted command receipt and profile readback |
| Source manifest is exact | Repeated manifest generation and JSON parse |
| Target manifest is exact | Repeated manifest generation and profile readback |
| Every delta is classified | Deterministic classification test |
| Conflicts fail closed | Fixture with missing metadata and digest mismatch |
| No mutation occurred | Command audit plus repository diff review |
| Human and machine readbacks agree | Byte-stable JSON/Markdown parity check |

## Stop conditions

- Any write-capable command is selected or required.
- Credentials or session material would need to be stored or printed.
- Source or target identity cannot be proven from the approved profile.
- A provider response omits exact keys or digests needed for classification.
- Any conflict is resolved by recency, aggregate count, filename, or guess.

## Out of scope

Cloudflare copy, delete, retirement, deployment, DNS, Access, tunnel,
Vectorize, D1/KV/R2 mutation, Telegram proof, Hermes EC2 update or restart,
Desktop reconnection, directive execution, and selection of the first D1
WorkObject candidate.
