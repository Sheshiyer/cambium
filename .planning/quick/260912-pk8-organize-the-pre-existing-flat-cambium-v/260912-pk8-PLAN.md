# Organize the existing Cambium visual-flow images

## Goal

Create a deterministic, mapped, renamed source library for the 46 pre-existing image assets stored flat in `docs/assets/visual-flow/`, while keeping their original numbered files unchanged.

## Structure

- `source-library/telegram-mini-app/` for boards, mobile screens, and motion studies.
- `source-library/r3f/organs/` for explicitly named Genesis, Hands/Build, Cortex, Will/Ops, and Taste lineage references.
- `source-library/r3f/components/` for reusable named semantic specimens.
- `source-library/r3f/mesh-turntables/` for Genesis and Rail Arc view variations.
- `source-library/r3f/unresolved-models/` for visually distinct but unproven organ identities.
- `source-library/r3f/product-pages/`, `brand/`, and `contact-sheets/` for their bounded source roles.

## Constraints

- Copy non-destructively; do not rename or delete the numbered originals.
- Preserve duplicate relationships rather than silently deduplicating files.
- Do not infer organ identity for the five unnamed model previews.
- Retain source number, original filename, dimensions, hash, category, and adaptation role in a machine map.
- Do not modify Organ Console exports, runtime code, deployment state, provider configuration, or unrelated dirty work.

## Verification

- Exactly 46 source assets are mapped and exported.
- Every exported SHA-256 equals its numbered source.
- All renamed destination paths and source IDs are unique.
- Four known duplicate pairs remain explicit.
- The five unnamed model previews remain marked unresolved.
- Existing root images and the Organ Console package remain unchanged.
