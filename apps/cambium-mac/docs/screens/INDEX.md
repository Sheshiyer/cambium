## Visual inheritance

Preserve petrol/teal terrain, ivory information, chartreuse selection, mint facts,
peach holds, copper edges, contours, rails, packet markers and stable organ
glyphs. Adapt imagery to native layout and readable text. Numeric values,
“ONLINE,” rings, latencies and sample counters in source artwork are illustrative.
They cannot populate a production view model.

Hands/Will retain canonical IDs while Build/Ops may remain display aliases.
Cortex can appear central visually but remains cross-cutting in the model.
Eleven portraits identify roles, not eleven independently healthy services.

Source instructions sometimes specify web/mobile 44–45px targets. Native control
metrics require platform-specific review; do not copy CSS pixel thresholds into
SwiftUI points without checking macOS interaction and accessibility.

Flow, Actions, Plant Health and earlier Organ Atlas page studies have recorded
holds. Later source implementations do not retrospectively accept held art.
Superset, Constellation and Paperclip remain retired historical references.

## Screens and complete state coverage

| ID | Screen / job | Input | Main action | Required state cases |
| --- | --- | --- | --- | --- |
| N01 | Canopy: understand the system | Source topology + scoped observations | Select work or attention item | Loading, populated, empty, source-only, stale cache, denied, unavailable |
| N02 | Work dossier: understand one finite pursuit | Exact WorkObject + mission/plan joins | Open evidence or permitted next step | Complete/missing metadata, blocked, ambiguous identity, expired review |
| N03 | Flow trace: follow one lineage | Mission/task/loadout/attempt/evidence | Inspect one typed edge | Observed, source-only, missing join, delayed, rejected, revoked |
| N04 | Evidence inspector | Source/receipt/artifact/verdict | Open source or independently read status | Valid, malformed, wrong subject, stale, missing consumer/verdict |
| N05 | Gate review | Full server-owned proposal tuple | Deliberate exact decision, required v1 | Ready, changed, expired, refused, confirming, submitting |
| N06 | Decision journal | Immutable matching receipt | Reopen and query original-tuple status | Approved, rejected, conflict, unknown, disconnected queue |
| N07 | Knowledge and Possible | Scoped citations / user-selected Field Theory node | Open owner or prepare candidate | Available, denied, stale, absent CLI, model-derived, unresolved work join |
| N08 | Connections | Per-owner identity/schema/observation | Inspect/reconnect through owner | Unknown, checking, ready, denied, offline, expired, unsupported |
| N09 | Settings / design gallery | Local preferences and semantic tokens | Change reversible local preference | Light/dark, high contrast, reduced motion/transparency, VoiceOver |
| N10 | Source-world lens, optional | Authored districts/topology | Explore and return to exact selected work | Source-only labels, keyboard path, static fallback, no exploration progress as work |
| N11 | Launch and run | Fresh owner-issued admission/capability and exact request/attempt | Launch admitted work, inspect result, reconcile original request | Eligible, refused, busy, queued, running, terminal failure, result ready, acceptance missing, interrupted, outcome unknown |

The opening route is N01 → N02 → N04 → an available read, evidence request,
proposal preparation or owner review. N05 is not automatically the next action.
The founder-selected first release also includes deliberate N05 decisions and
N11 launch of already-admitted work, with result and recovery. A read-only route
is an intermediate slice rather than a substitute release scope.
Walking/orbiting is optional; search and the linear inspector must expose the
same identities and evidence. Preserve selection across lens changes.

## Snapshot and interaction plan

After native implementation, capture every screen, review sheet, panel, settings
tab and component state in light/dark. Include narrow/large windows, long text,
keyboard focus, window activation, zoom/text scaling and reduced motion. Seed
data must be synthetic and visibly labelled; state the producing code revision.

Use real controls, semantic token layers and named icons. An accessible list
must expose the graph's same work and source meaning. Test read races, failed
refresh and principal changes without erasing a retained valid receipt or
repainting a newer read with an older response. Never animate unobserved stages.

No native snapshot or prototype acceptance has been claimed at this checkpoint.
