# Cambium

Research draft, 2 November 2026. Native product discovery; no scaffold, install,
release or runtime activation. Acceptance stays in root `ISA.md`, ISC-3140–3171.

## Purpose

A native Mac home for understanding the Thoughtseed/Cambium system and choosing
the next meaningful action from its actual evidence, owners and constraints.
Founder interview: **“See the whole system, then choose the next meaningful action.”**

## Replaces

The daily need to reconstruct context across source maps, Curious, portfolio
planning, runtime glass, knowledge references and decision receipts. Existing
owners and peer surfaces continue to operate through their own contracts.

## Main jobs

1. See what exists, what changed, and which work deserves attention.
2. Focus one WorkObject and understand its purpose, dependencies, current
   objective, evidence, gaps and available next step.
3. Follow that step to a source, evidence request, review or owning application;
   make deliberately reviewed canonical decisions and launch already-admitted work
   through the owning execution plant, then inspect results or recover uncertainty.

## Data

- Work reference: canonical ID, portable repository identity, owned component,
  tenant/read scope, source revision and digest.
- Observation: producer, schema, subject, source time, observed time, expiry,
  provenance and explicit unavailable/held reason.
- Work lineage: mission → task → pinned loadout → attempt → artifact → receipt
  → consumer acknowledgment → independent verdict → bounded learning proposal.
- Local preferences/cache: selection, layout, appearance, source bookmarks and
  disposable read caches; never an independent operational ledger.

## Shape

Proposed sidebar window with a Canopy overview, focused dossier and inspector;
optional spatial exploration and later small entry points. macOS 26+ is the
Bama baseline, pending product support decision. The founder confirmed an initial
founder/operator audience, preserving tenant and role boundaries; broader
team/external distribution is later scope.
Networked owner reads are fundamental. Offline mode explains cached/source-only
information and withholds current action authority.

## System hooks

Native menus, keyboard search, source deep links, user-selected Field Theory
reads, deliberate decisions and launch of already-admitted work are in the
first-release design. Hands/Hermes launch uses owner-specific admission and run
interfaces. Menu bar, notifications, Shortcuts and CLI/MCP automation each need
a separate story and permission model.

## Reference and look

Cambium's visual-flow source library, Organ Console, system atlas, Expedition
Dossier and Gate chamber. Petrol/teal terrain, ivory content, chartreuse focus,
mint evidence, peach holds, copper rails and distinctive organ glyphs. Native
controls, accessible typography and progressive disclosure frame that language.
No fixture metric or illustrative animation becomes a live fact.

## Not in the first implementation slice

- Replacing D1, ISA, GSD, Field Theory, Hermes, Plexus or runtime ownership.
- Unreviewed execution, publication, paid calls, schedule activation or policy edits.
  Explicit launch of already-admitted work is in v1, through its existing owner.
- Retiring Electron/Curious, copying native histories, or migrating machines.

## Bama adaptation

Use the inspected Bama workflow for brief → source/screen research → stories →
native scaffold → design kit → bounded implementation and verification. Its
generic personal-app scope reduction cannot remove Cambium's required identity,
tenant, network or integration boundaries. This folder is inside the existing
repository; no nested Git initialization or automatic install is appropriate.
