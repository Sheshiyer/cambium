### Learning

The useful system boundary is not “the UI”: it is a chain of projections,
authorities, evidence modes, and gates. A single route-level capture config
can make a console look ready while leaving the visual shells, hosted
Workbench, Mini App, Worker, and connected systems unexplained. A canonical
surface inventory is therefore the reusable upstream fix. The next run should
refresh stale bridge health before any screenshot claim, and should retain
boundary-map-only treatment for systems without owner-authenticated evidence.

### Root-cause decision

The bad state entered upstream where one guide configuration represented only
the Manifest console while Cambium exposes several independent UI and service
boundaries. The corrective action is a canonical multi-surface inventory and
coverage contract. This removes three recurring classes of drift—missing UI
surfaces, connected-system authority confusion, and capture claims without
evidence—before any renderer or trigger behavior is touched. The analysis
traces source-up for documentation ownership and display-down only for live UI
verification.
