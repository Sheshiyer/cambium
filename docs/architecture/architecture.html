2 · Data flows between services

The composition/operator plane plans; the runtime plane executes and receipts; projections observe without authority.

  • Plan flow: compose/operator validates registry, pipeline, adapters, and spend gates locally before any runtime invocation.
  • Runtime flow: the Quests Worker serves quest envelopes, directives, action receipts, lead runs, and context routes under tenant scoping.
  • Knowledge flow: company knowledge enters only through the Plexus GitHub-App gateway as redacted excerpts bound to exact commit SHAs.
  • Foldback flow: evidence and learning may inform future intents only through signed Gate approval plus the D1 compare-and-set path — projections can never feed themselves back as fresh authority (fail-closed).
  • Integration spine: portfolio identity → typed systems graph → mapping receipt → reviewed packet → D1 admission → loadout pin → Hermes execution → terminal receipt → foldback proposal (see INTEGRATION.md).

5 · Intent Graph, Temperance flow, and GSD operating model

Added since the previous refresh. Full contracts: goal-graph-operating-model.md, intent-graph.md, temperance-flow.md.

Intent Graph read-only

Deterministic projection of vision → mission → finite goals → tasks → evidence → learning. Every node carries source path, named authority, lifecycle, digest. It can inspect but never set doctrine or approve work (cambium.intent-graph-projection.v1).

Temperance flow read-only

Derives one exact next action from authority precedence (ISA goal → GSD state → active plan), exposing route, combo/lane intent, gates, freshness, stop conditions, and blocked reasons. Ambiguity yields blocked, never a competing plan.

GSD phases 3–7 operating model

Phase 3 canonical anchors · Phase 4 provenance-preserving intent graph · Phase 5 Ralph + Temperance flow projection · Phase 6 documentation stewardship · Phase 7 deterministic safety and handoff (rejects authority drift, stale or sensitive projections; reviewed handoff closes each phase).

  • Approval-bound commits: tenant, source reference, node set, policy decision, actor, and expiry bind into an approval digest; commits apply only when digest, approval, and writer lease still match the expected graph revision.
  • Pinned execution: graph version, policy/catalog version, and adapter version are pinned per task and receipt; retries replay that identity exactly.
  • Reconciliation: split/merge lineage stops for human review — proof is never inherited by guessing.

6 · Business objective (ISA Goal)

Consolidate Cambium's doctrine into a provenance-preserving infinite-game architecture anchored by canonical VISION.md and renewable MISSION.md, with ISA and GSD as the only goal/planning authorities. Map vision → mission → finite goals → tasks → evidence → learning as a fractal graph, and expose next actions, skill-cluster and gateway flows, gates, and stop conditions through Temperance.
  • Product promise: an idea goes in; a self-running, on-brand business comes out. The composition layer makes the first launch; the operator keeps the venture alive as an infinite game.
  • Business model: the left brain (build) is free; the right brain (taste + brand memory) is the subscription — compounding brand memory is the moat.
  • Fractal shape: the same operating pattern scales from founder-led business to marketing team to AI-first product, runnable from synthetic demo tenants without private data.
  • Standing safety claims: no automatic outreach, no publication, no recurring engagement schedules, no unreviewed paid-provider calls — every such surface is fail-closed until a signed gate opens it.
