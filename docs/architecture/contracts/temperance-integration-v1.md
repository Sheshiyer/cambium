# Temperance integration boundary

Temperance Engine is a standalone hand-in-glove product. It can operate without
Cambium. Noesis Cambium is the optional personalized integration for Thoughtseed.
Cambium owns the company operating model and its integral view.

The adjacent JSON contract declares this boundary. It does not enroll a project,
admit work, change D1, configure a provider, or enable an executor.

## Repository ownership

| Repository | Changes that belong here |
|---|---|
| temperance_engine | Generic kernel, modules, installer, CLI/native adapters, control and projection contracts |
| noesis-cambium | Personal Thoughtseed profile, sovereign context joins, OmniRoute bindings and company adapters |
| cambium | Company graph, Gate, WorkObjects, approved operating-organ work, delivery policy and company integration contract |

Git history must remain scoped to the owner. Do not move private runtime stores,
keys, native sessions, personal memory, or company records into the public product.
Reusable source can be promoted with provenance; live state cannot be copied as source.

## Configure each boundary

The product needs a selected native coordinator, a private host binding and optional
modules. Git workspaces can operate without Superset. Its inspector reports missing
configuration and typed holds; it does not grant execution.

Noesis Cambium needs the selected Thoughtseed plant, private routing/skill/workspace
bindings, bounded context references and explicit company integration admission.
Keep the symbolic profile separate from machine paths and secret values.

Cambium needs its existing tenant/member identity, signed Gate, approved WorkObject,
ISA criteria, finite GSD task, executor lease, artifact/verdict and owner readback.
Plexus resolves identity. Hermes owns admitted remote execution. D1 remains the
operational writer. Reference-only seams never become another writer.

HeyZack hosted OmniRoute is a separate plant. Snow Gloves fleet is outside this
integration. No key, account, quota, database or fallback policy crosses automatically.

## Source proof and remaining gates

Run `node scripts/check-temperance-integration.mjs` to validate the portable owner
contract. This command reads one committed contract and emits a metadata report.
It does not contact services or establish runtime readiness.

Next gates: accepted cross-owner lineage, missing/duplicate callback recovery,
git-only workspace admission, pre-consumption account/fallback enforcement, durable
A2A cancellation, typed Constellation control, common projections, and independent
plant-specific release proofs. Keep source, installed, runtime and UAT distinct.
