# Optional cited text context

`CortexTextStore` is a provider-neutral text retrieval seam alongside vector `CortexStore`. It preserves ordered ranks and source citations without inventing cosine scores. The HTTP client binds one tenant/project/plane/audience/member scope, refuses redirects, bounds requests/responses and rejects authority or credential echoes. Default recall is two cards/1200 characters; hard limits are eight/8000.

A trusted composition owner can supply `textStore` and `textScope` to `wakeAsync`. Meso/macro results return separate `textContext`; the pure wake decision and vector Recall remain unchanged. Unavailable or denied retrieval remains explicit advisory data and cannot authorize effects.

The standalone `bin/operator/cortex-text-cli.ts` takes `--scope-file ABS --query TEXT`. The private0600 file stays outside this repository and contains `{endpoint,scope}` only; the reader credential comes from `CORTEX_TEXT_TOKEN`. This entry point does not initialize a world, tenant registry or vector store.

`readFoldbackText` accepts a trusted existing Hermes reader, exact immutable key/binding and explicit scope. The owner must construct that reader with the existing external admission verifier. Missing admission stays held; exact receipt/task/execution/WorkObject lineage and canonical bytes are required. The bounded terminal note is a projection with `effectsAuthorized:false` and `semanticAcceptance:false`. A terminal executed outcome is not project ISA acceptance.

Company-specific backend selection, writer policy, source manifests, tokens and Hindsight deployment remain outside this product boundary. No raw receipt or caller acceptance flag becomes a trusted read path.

Validation: text client, orchestration, foldback and existing wake/Hermes focused suites pass61 tests. Direct client/CLI strict checking passes. Broader repository audit failures are recorded in the active project handoff; this addition does not claim repository-wide deployment acceptance.
