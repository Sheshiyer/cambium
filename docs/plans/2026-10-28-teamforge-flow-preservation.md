## Schema and identity reuse

`cloudflare/worker/src/lib/project-registry.ts` separates workspace-scoped projects, client association, many GitHub repository links (roles/primary/sync flags), Huly links, artifacts, external IDs, and sync policy. Preserve those distinctions. A repository reference is neither a WorkObject ID nor a planning authority, and `is_primary` is not reviewed planning admission. Migration `0005_project_identity_links.sql` adds client linkage and external-ID indexes; it does not establish Cambium graph admission.

Cortex nodes (mission/client/project/issue/agent/human/memory/routine/approval), paths (ownership/execution/handoff/risk/memory/routine), and presentation states (healthy/active/pending/blocked/dormant/archived) are display vocabulary. Do not directly cast them to Goal Graph lifecycle values. Source `buildMissionGraph.ts` aggregates source datasets; it is not a replacement for Cambium's operational writer. Source sample data must stay visibly synthetic.

Cambium already has `plexus-work-reference.ts` (exact actor/tenant/resource/active-node checks), `lib/plexus-principal.ts` (Access plus Plexus identity), `plexus-knowledge.ts` (gateway provenance), `goal-graph-intake.ts`, and `organ-update-delivery.ts`. Contracts `plexus-work-reference-v1.md`, `branch-mission-fabric-contract.md`, and `github-backed-knowledge-plane.md` preserve these ownership boundaries. TeamForge's active Cloudflare routes/migrations remain in their source repository; no migration or Worker code is moved.

## Recommended first runtime slice — scope for review only

Use the existing Curious World landmark folio in `apps/cambium-r3f/src/curious-world/index.ts` as the host. Its `openFolio` source-landmark presentation already renders a dossier, relationships and explicit “no live mission state” copy. Reuse TeamForge’s node selection → details → trace-source interaction there, without adding its shell, seven global navigation tabs or command execution. `mission-dossier.ts` is reusable presentation guidance but validates a pending canonical Gate change; it must not be used to label a committed WorkObject read as a pending proposal. Leave Gate review/signing and `GateSnapshot` untouched.

The minimal first slice should be a read-only trace panel for a selected WorkObject: exact identity/kind/node, committed graph version/digest, checked-at time and explicit verified/unavailable/stale/rejected states. Reuse the existing `plexus.work-reference.v1` receipt shape rather than inventing another graph authority. Never infer owner, objective or task status from that receipt: it intentionally excludes those fields. Add knowledge excerpts only through the existing provenance-bearing gateway contract in a later slice.

Important inspected prerequisite: `plexus-work-reference-v1.md` explicitly marks the resolver as a local prerequisite with no route or installed adapter. Its current Plexus principal resolver emits tenant `*`, which is deliberately rejected. Consequently a live trace panel cannot be wired by passing request tenant into that principal or by treating role/allow as a resource grant. The first implementation scope must include a server-owned exact tenant/member/resource binding and fresh resource-grant producer, then a read-only bridge method separate from GateBridge; if that producer is not available, the panel stays unavailable. The exact authoritative grant source and its revocation freshness are the remaining engineering decisions. The user need not choose UI internals; the proposed host and minimal fields above are the recommendation.

Proposed acceptance: exact selected node and scope binding, malformed/wildcard principal denial, expired/revoked grant refusal, stale graph response, missing adapter/unavailable state, keyboard/narrow-screen inspection, and zero action/decision/network-mutation calls. Runtime implementation awaits approval of this bounded scope. No runtime, auth or projection contract is changed by this document.
