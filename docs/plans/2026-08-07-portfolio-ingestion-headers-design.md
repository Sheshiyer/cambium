# Portfolio Ingestion Headers Design

**Date:** 2026-08-07
**Status:** implemented and locally verified; production promotion governance-held
**Owner:** Cambium

## Problem

Production still serves Portfolio Workbench v3, so Unplanned cards expose `Now`, `Next`, `Later`, `Park`, and `Needs review` even though repository-first v4 is merged. The standalone destination now holds 47 shallow Thoughtseed folders and 30 shallow Tryambakam-Noesis project candidates, but the Workbench has no portfolio header for the second root and no portable mapping between folders and portfolio grammar.

The folder hierarchy must not encode the missing semantics. The ratified destination grammar is shallow: one portfolio root followed by one repository folder. Adding `client-branches/`, `saplings/`, or `projects/` directories would recreate nested-repository ambiguity and change every canonical address again.

## Grammar

### Thoughtseed

- Thoughtseed-originated venture folders may propose Saplings.
- Client-originated folders propose Client Branches grouped by exact source `accountId`.
- Shared company/capability folders propose Internal Programs.
- Ambiguous origin remains Needs Review.
- Folder proposals do not rewrite the canonical WorkObject registry.

### Tryambakam · Noesis

- The portfolio unit is `Project`.
- It is not a Thoughtseed client account and its projects are not Client Branches.
- `.agents` was absent from the final exact-set snapshot and is not rendered as a Project.
- `_archive` is a lifecycle container.
- `selemene-engine-worktrees` is worktree infrastructure.
- The remaining 30 shallow folders are ingestion candidates, not automatically verified repositories.

## Approaches considered

### 1. Physical type directories

Move repositories beneath `client-branches/<client>/`, `saplings/`, `programs/`, or `projects/`.

Rejected because it violates the shallow destination grammar, changes every address, and can turn containers into accidental Git boundaries.

### 2. Symlinked navigation trees

Keep canonical folders shallow and add a second hierarchy of symlinks.

Rejected because tools and humans would see two valid-looking paths, weakening session, worktree, and planning-authority joins.

### 3. Portable mapping headers

Keep every folder in place. Commit one relative-path snapshot, render it as portfolio headers in the Workbench, and generate `PORTFOLIO.md` plus `portfolio-map.v1.json` at each root.

Chosen because it preserves one address per folder, is reversible by deleting two header files, supports future ingestion, and makes classification uncertainty visible.

## Architecture

`docs/project-management/portfolio-roots.v1.json` is the reviewed proposal snapshot. It contains portfolio-relative folder names, proposal kind, client account where applicable, linked WorkObject identifiers, and bounded notes. It contains no absolute machine path and no repository content.

`apps/portfolio-cartographer/scripts/generate-portfolio-root-map.mjs` validates the snapshot, emits a typed browser module, and optionally writes root headers only when an explicit projects root and write flag are supplied. Header generation first proves the observed shallow directory set exactly matches the snapshot. It may write only `PORTFOLIO.md` and `portfolio-map.v1.json`; it never creates, renames, moves, deletes, or traverses repository descendants.

The Workbench adds a portfolio selector:

- `Thoughtseed` keeps the existing WorkObject board. Client-family headers receive bounded folder receipts and unresolved families retain explicit mapping gaps.
- `Tryambakam · Noesis` renders one `Projects` group. Each active candidate is labeled `Project`, `Awaiting ingestion`, and exposes one `Inspect project intake` action. Archives and infrastructure are distinct summaries, not project cards.

The browser remains offline and proposal-only. It consumes generated bytes and never reads the founder filesystem.

## Interaction model

An unresolved Thoughtseed card exposes only `Review repository & map` (with an accessible `Inspect & reconcile` name). A Tryambakam-Noesis folder exposes only `Inspect project intake`. Neither control schedules work. Selecting a Tryambakam project opens a bounded intake drawer containing the relative folder, proposal status, and missing GitHub/WorkObject evidence; Plan and Delivery remain absent until later ingestion establishes authority.

## Production boundary

The current production v3 observation is recorded separately from the merged artifact. Build, route parity, local browser proof, and a strict Worker dry run may proceed. No Worker Version upload or traffic promotion occurs while issue #292 is open and the Cambium packet remains `draft-held`.
