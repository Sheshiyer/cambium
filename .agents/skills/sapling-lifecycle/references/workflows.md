# Workflow composition

The maintained source is Cambium's repo-local `sapling-lifecycle` skill. Each catalog component points to its owning source; no workflow body or private source corpus is forked here. Source roots are supplied locally as Cambium, vault, and skill-clusters roots. Missing optional roots are visible gaps, not runtime prerequisites for the whole pack.

| Product frontier | Existing component | Needed evidence and result |
| --- | --- | --- |
| New seed | `sapling-product-intake`, `project-birth` | Origin, founder intent, beneficiaries, repository roles and reviewed identity. Prepare first; do not mint admission. |
| Existing product | `product-branch-packets`, `packet-read-model` | Read the current packet, source/evidence/gate ledgers and loop control inputs. Separate proof-only from supervised or autonomous status. |
| Evidence refresh | `sapling-product-loop` | Bind app/site roots, inspect four surfaces, merge graph, fence claims. Scratch output only on this read route. |
| Brand and home | `website-delivery` | Existing brand authority and one composition path; media rendering and publication follow their own request boundaries. |
| App implementation | `expo-rn-app`, `cloudflare-workers`, `supabase-app` | Choose by actual product stack. Preserve native, tenant, binding, and migration constraints from the owning repository. |
| Native release | `native-macos-release` | Pinned source, release contract, local trust evidence, then separately authorized uploads/publication. |
| Launch materials | `brand-case-loop`, `cambium-social-thread` | Product-specific proof and allowed platforms. The social-thread source is Cambium/Temperance-specific. Queued drafts are not sent. |
| Discoverability | `search-stack-run` | Bind the WorkObject and inspect foundation plus SEO/SMO/AEO/GEO/DEO/SXO. Unknown scores remain unknown. |
| Channel experiment | `sapling-multi-prong-gtm`, `gtm-loop-evaluator` | Current brand context, selected channel and attributable observations. Historical calibration never supplies current approvals. |
| Learning | `gtm-learning-compiler`, `gtm-handoff-compiler` | Separate historical data and current observations; review compiler fit. Output is a candidate lesson/handoff, with no automatic delivery or memory write. |
| Repetition | `branch-loop-library` | One objective, metric, boundary, stop rule and proof requirement. One round changes one thing or records one blocker. |
| Closeout/renewal | `project-closeout` | A reviewed disposition, preserved handoff and successor ownership. Preparation does not retire or relocate anything. |

For a selected step, read its catalog row and owning source, confirm inputs and prerequisites, state the expected outcome, perform only the authorized work, and verify the outcome using the owning check. Record the source revision and whether the check was local, mocked, staging, authenticated live, or owner accepted.

The catalog's `verify` field identifies an owning verification command. Reading the catalog does not run it, and a command listed there is not a passing test receipt. Grok `inspect` checks discovery only; semantic workflow completion requires a terminal workflow result.

A compound product goal can take several commands. Resume from the last verified result rather than running completed external actions again. A status read may refresh evidence without advancing a step.
